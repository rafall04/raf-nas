01

Ringkasan eksekutif

Yang tersedia sekarang adalah design handoff frontend kelas atas: 11 layar hi-fi, design token light/dark yang sudah diaudit WCAG, copywriting Bahasa Indonesia, dan perilaku antarmuka yang rinci. Itu aset berharga — tetapi ia menjawab tampilan, bukan mesin.

Membangun sebuah NAS adalah 75–85% pekerjaan backend dan integrasi: penyimpanan file, autentikasi, model data, mesin hak akses, audit, dan operasional server. Bagian itu belum ada sama sekali di repo. README pun mengakuinya secara eksplisit — desain diasumsikan “dibuat ulang di dalam codebase target” yang belum dipilih.

Jebakan “salah jalan” yang paling mahal

Memperlakukan aplikasi sebagai sumber kebenaran padahal file diubah di luar aplikasi. Tiga keputusan arah di bawah menetralkan jebakan ini sepenuhnya — itulah kenapa keduanya diambil lebih dulu.

02

Keputusan arah yang sudah dikunci

Empat keputusan induk yang menentukan seluruh arsitektur turunannya. Diambil bersama pemangku keputusan pada 7 Sep 2026.

Kepemilikan
Produk milik RAF — akan dipakai-ulang / dijual ke pabrik lain. Karena itu build custom dibenarkan demi kepemilikan IP; reskin Nextcloud (AGPL) / Seafile Pro dikesampingkan.
Identitas
Tanpa Active Directory → autentikasi memakai akun lokal aplikasi (argon2id). Seluruh alur Login di mockup — wajib ganti sandi, 2FA admin, rate-limit, “Ingat saya” — jadi relevan penuh.
Jalur akses
Web-only — tidak ada pengeditan paralel lewat drive jaringan (SMB). Konsekuensinya besar: aplikasi boleh menjadi sumber kebenaran.
Stack
React + TypeScript + Vite (frontend) · NestJS / Node (backend) · PostgreSQL (audit 24 bulan) · object-store di NTFS berbasis fileId/versionId.
03

Efek keputusan “web-only”: penyederhanaan besar

Karena hanya aplikasi yang menulis ke file store, tiga jebakan terberat dari analisa awal lenyap — dan fokus effort berpindah ke hal yang benar-benar bernilai.

Hilang Tidak perlu lagi

  • Rekonsiliasi USN Journal / watcher — DB & disk konsisten karena satu penulis.
  • “Confused deputy” — otorisasi cukup di API; NTFS ACL hanya mengunci store ke akun service.
  • Deteksi lock SMB (“sedang dibuka oleh X”) — dibuang atau di-scope ulang jadi “sedang diedit lewat web”, opsional.
  • Memalsukan riwayat versi dari snapshot VSS.

Tetap Fokus effort tersulit

  • Tabel file virtualized — mulus di 5.000 baris.
  • Mesin hak akses — matriks Group×Ruang + 4 peran + pengecualian per-folder + superuser.
  • Auth custom lengkap — 2FA admin, rate-limit per-akun & per-IP.
  • Audit append-only retensi 24 bulan + ekspor CSV ter-stream.
  • Keamanan link publik — hash argon2id, slug ≥16 char, rate-limit.

Bonus: riwayat versi jadi bersih

Tiap unggah web = copy-on-write versi lama sebelum menimpa. Fitur murni aplikasi, per-save, tanpa perlu didamaikan dengan snapshot sistem.

04

Arsitektur target

Satu server, LAN pabrik, tanpa internet. Otorisasi ditegakkan di API; file logis di DB, file fisik di object-store ber-id sehingga rename/pindah tak pernah menyentuh disk dan tak memutus referensi versi/link.

05

Model data inti & mesin hak akses

Entitas inti

  • User — id, nama, username, sandi (argon2id), status, 2FA.
  • Group & keanggotaan.
  • Ruang — id, nama, kuota, kebijakan snapshot.
  • Node — file/folder, path logis, kategori, ukuran, pemilik.
  • Version — per node, copy-on-write, penanda “saat ini”.
  • Grant — {group, ruang, peran} + FolderException {path, group, peran}.
  • ShareLink — slug, hash sandi, kedaluwarsa, batas unduh.
  • AuditEvent — append-only, before/after, retensi 24 bln.

Aturan resolusi izin (tetapkan sebelum coding)

  • User di banyak group → ambil peran tertinggi dari union grant ruang.
  • Pengecualian folder paling spesifik (path terpanjang) menang atas grant ruang.
  • “Tidak ada akses” selalu menang (deny-override) atas grant mana pun.
  • Superuser Admin IT = group global yang bypass matriks, dengan audit khusus. (kini tak dimodelkan — harus ditambahkan.)
  • Satu sumber kebenaran tunggal: matriks. Halaman Ruang diturunkan darinya. (kini bertentangan.)
  • Penegakan di server; tombol nonaktif di UI hanya kosmetik.

09

Keamanan non-negotiable

Kelas kerentanan yang gratis dicegah di desain API, tapi mahal ditambal setelah rilis — dan produk yang mungkin dijual ke banyak klien menanggung risikonya berlipat.

  • Penegakan izin di server; filter listing & search per-izin.
  • Hash sandi argon2id; tak pernah plaintext.
  • Sandi link publik = hash + tampil sekali (bukan reversible seperti mockup).
  • Slug link ≥16 char CSPRNG + rate-limit + respons generik “Tidak ditemukan”.
  • Lockout login per-akun DAN per-IP; sisa-percobaan dari backend.
  • “Ingat saya” default OFF di PC bersama + idle timeout pendek.
  • Content-Disposition: attachment + X-Content-Type-Options: nosniff.
  • Validasi tipe via magic bytes + nama/path NTFS + cegah traversal.
  • Audit append-only, tamper-evident, ekspor CSV UTF-8+BOM.
  • AV scan (Defender/ClamAV) saat finalisasi sebelum file tersedia.
10

Keputusan kebijakan yang masih terbuka

Bukan penghalang mulai (arsitektur sudah jelas), tapi harus disepakati sebelum fitur terkait dibangun.

  • Penyimpanan Windows: satu volume + kuota app vs volume-per-ruang.
  • Snapshot & backup: produk (Veeam / Windows Server Backup), RPO/RTO, UPS.
  • Sampah: per-ruang; siapa boleh kosongkan; kuota memperhitungkan sampah.
  • Zona waktu resmi (WIB) untuk semua timestamp & kedaluwarsa.
  • Pratinjau XLSX: “unduh saja” (MVP) vs render server (fase lanjut).
  • Batas unduh link: per-event vs per-file; “Unduh semua” = 1 atau N.
  • 2FA admin: alur enrol + kode pemulihan + jalur bila admin terkunci.
  • Pemeliharaan pasca-rilis: kontrak RAF vs 1–2 admin SFL.
